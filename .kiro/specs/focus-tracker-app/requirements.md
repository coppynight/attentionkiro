# Timelog 需求文档

## 产品理念

**人生就是一个项目，你花费的时间就是在向人生的git提交记录，你还可以给你的美好时刻打上tag。**

Timelog（时间日志）是一个充满诗意的时间管理应用，将人生比作一个代码项目：
- 每一分钟的时间使用都是一次 **commit**（提交）
- 每个时间块都可以添加 **tag**（标签）来标记美好时刻
- 时间热力图就像 GitHub 的记录图，展示你的人生活跃度
- 智能分析帮你回顾人生的 **commit history**（提交历史）

## 产品愿景

让用户以程序员的视角审视自己的人生：
- **可视化时间记录**：通过热力图展示每天的时间投入
- **标记美好时刻**：为重要的时间片段打上有意义的标签
- **回顾提交历史**：智能分析时间使用模式和习惯变化
- **优化人生代码**：基于数据洞察提供生活改进建议

## 核心功能

### ⏰ 时间管理（Time Management）
整合了时间记录图和时间标签功能的综合时间管理界面：

#### 🔥 时间记录图（Time Record Graph）
- GitHub风格的24小时热力图，展示每天的"时间记录"
- 颜色深浅代表专注强度，就像时间记录的活跃度
- 支持查看历史数据，回顾人生的精彩时刻

#### 🏷️ 时间标签（Time Tags）
- 为时间块添加有意义的标签，就像给代码提交打tag
- 预设标签：工作、学习、娱乐、社交、运动、阅读等
- 支持自定义标签，记录个人化的美好时刻

### 🧠 智能洞察（Life Analytics）
- 分析时间使用模式，就像代码质量分析
- 提供个性化的生活优化建议
- 识别高效时段和改进空间

### ⚙️ 设置管理（Project Settings）
- 配置时间块粒度，就像设置代码提交频率
- 数据导出功能，备份你的人生数据
- 标签管理，维护你的人生标签库

## 需求

### 需求 1：人生提交记录（Life Commit Tracking）

**用户故事：** 作为一个想要记录人生每一次"提交"的用户，我想要应用能够自动追踪我的时间使用，这样我就能看到自己的时间记录图，就像程序员查看GitHub记录图一样。

#### 验收标准

1. 当用户开始一个时间段时，系统应当创建一个新的"时间提交"记录
2. 当用户结束一个时间段时，系统应当完成这次"提交"并计算时长
3. 当系统检测到连续的专注时间时，系统应当将其标记为"高质量提交"
4. 当用户的时间使用出现中断时，系统应当记录"提交冲突"并标记原因
5. 当一天结束时，系统应当生成当日的"提交摘要"，包含总时长和主要活动
6. 当用户查看历史数据时，系统应当以类似GitHub记录图的方式展示时间热力图
7. 当系统检测到用户的"提交频率"变化时，应当在热力图中体现活跃度差异
8. 当用户连续多天保持活跃时，系统应当在热力图中显示"连击"效果

### 需求 2：时间记录图（Time Record Graph）

**用户故事：** 作为用户，我想要看到自己的时间记录图，这样我就能像查看GitHub记录图一样，直观地了解自己每天的时间投入和活跃程度。

#### 验收标准

1. 当用户打开热力图页面时，系统应当显示GitHub风格的24小时时间热力图
2. 当用户查看热力图时，系统应当用颜色深浅表示每个时间块的专注强度
3. 当用户点击热力图中的时间块时，系统应当显示该时间段的详细"提交信息"
4. 当用户查看不同日期时，系统应当动态更新热力图显示对应日期的数据
5. 当用户查看统计卡片时，系统应当显示当日总时长、时间块数量和平均专注度
6. 当热力图显示高活跃度时，系统应当用深绿色表示，就像GitHub的深绿色记录
7. 当热力图显示低活跃度时，系统应当用浅色表示，保持视觉一致性
8. 当用户连续多天保持高活跃度时，热力图应当形成视觉上的"连击"效果

### 需求 3：人生代码审查（Life Code Review）

**用户故事：** 作为用户，我想要获得智能的人生代码审查，这样我就能像接受代码review一样，获得关于时间使用的专业分析和改进建议。

#### 验收标准

1. 当用户查看洞察页面时，系统应当显示时间范围选择器（本周/本月/本季度）
2. 当用户选择时间范围时，系统应当生成对应时期的"代码质量报告"
3. 当系统分析时间数据时，应当显示时间总览、平均每天时间和标记率
4. 当系统检测到时间分布时，应当按分类显示时间使用情况，就像代码模块分析
5. 当系统进行习惯分析时，应当识别最活跃时段、平均专注度和最常用标签
6. 当系统生成建议时，应当提供具体的"代码优化建议"，帮助改进时间使用
7. 当检测到时间使用模式变化时，系统应当在分析中高亮显示并解释原因
8. 当用户的时间使用效率提升时，系统应当给出正面的"代码质量评价"

### 需求 4：时间标签系统（Time Tagging System）

**用户故事：** 作为用户，我想要为我的时间块添加有意义的标签，这样我就能像给代码提交打tag一样，标记我人生中的美好时刻和重要活动。

#### 验收标准

1. 当用户查看时间标记页面时，系统应当显示当日的时间块列表
2. 当用户点击未标记的时间块时，系统应当打开标记界面，就像创建git tag
3. 当用户添加标签时，系统应当提供预设标签选项（工作、学习、娱乐、社交等）
4. 当用户创建自定义标签时，系统应当保存到个人标签库中供后续使用
5. 当用户为时间块添加备注时，系统应当支持详细的"提交信息"描述
6. 当用户查看已标记的时间块时，系统应当清晰显示标签和状态指示器
7. 当用户修改或删除标签时，系统应当提供简单的编辑功能
8. 当时间块被成功标记时，系统应当在界面上显示绿色勾选，表示"提交成功"

### 需求 5：项目设置管理（Project Settings）

**用户故事：** 作为用户，我想要管理我的人生项目设置，这样我就能像配置代码项目一样，自定义时间追踪的各种参数和选项。

#### 验收标准

1. 当用户打开设置页面时，系统应当显示分类清晰的设置选项
2. 当用户配置时间块粒度时，系统应当提供不同的时间间隔选项
3. 当用户管理标签时，系统应当提供添加、编辑、删除标签的功能
4. 当用户导出数据时，系统应当支持CSV和JSON格式，就像导出代码数据
5. 当用户需要清除数据时，系统应当提供安全的数据清理功能
6. 当用户查看应用信息时，系统应当显示版本号和关于信息
7. 当用户修改设置时，系统应当立即保存并应用新的配置
8. 当设置界面显示时，应当遵循iOS原生设计规范，保持界面一致性

### 需求 6：美好时刻标记（Beautiful Moments Tagging）

**用户故事：** 作为用户，我想要能够标记人生中的美好时刻，这样我就能像给重要的代码版本打tag一样，为特殊的时间片段添加有意义的标记。

#### 验收标准

1. 当用户发现特别有意义的时间段时，系统应当支持添加"美好时刻"标记
2. 当用户添加美好时刻标记时，系统应当提供特殊的标签样式和颜色
3. 当用户查看热力图时，被标记为美好时刻的时间块应当有特殊的视觉效果
4. 当用户回顾历史数据时，系统应当突出显示所有被标记的美好时刻
5. 当用户添加美好时刻时，系统应当支持添加详细的文字描述和感受记录
6. 当系统生成月度或年度总结时，应当专门展示用户标记的美好时刻集合
7. 当用户查看美好时刻列表时，系统应当按时间顺序展示，就像查看git tag历史
8. 当用户分享美好时刻时，系统应当生成精美的卡片，包含时间、标签和描述

### 需求 7：人生分支管理（Life Branch Management）

**用户故事：** 作为用户，我想要能够管理人生的不同"分支"，这样我就能像管理代码分支一样，清晰地组织和切换不同的生活模式。

#### 验收标准

1. 当用户创建新的生活模式时，系统应当支持创建"人生分支"（如工作模式、学习模式、休闲模式）
2. 当用户切换生活模式时，系统应当自动调整时间追踪的重点和标签建议
3. 当用户在不同分支间切换时，系统应当保持各分支的独立统计和分析
4. 当用户查看分支历史时，系统应当显示每个分支的活跃时间和主要成就
5. 当用户合并不同分支的经验时，系统应当提供跨分支的数据对比和洞察
6. 当系统检测到用户长期专注于某个分支时，应当建议适当的分支平衡
7. 当用户设定目标时，系统应当支持为不同分支设置独立的时间目标
8. 当生成报告时，系统应当显示各分支的时间分配和发展趋势

### 需求 8：人生版本发布（Life Version Release）

**用户故事：** 作为用户，我想要能够为人生的重要阶段创建"版本发布"，这样我就能像软件版本管理一样，记录和庆祝人生的重要里程碑。

#### 验收标准

1. 当用户达成重要目标时，系统应当支持创建"人生版本发布"记录
2. 当用户创建版本发布时，系统应当自动生成该阶段的时间使用总结和成就回顾
3. 当用户查看版本历史时，系统应当显示每个版本的发布时间、主要特性和改进点
4. 当系统检测到用户的显著进步时，应当建议用户考虑创建新的版本发布
5. 当用户分享版本发布时，系统应当生成包含数据可视化的精美报告
6. 当用户回顾人生历程时，系统应当以版本时间线的方式展示成长轨迹
7. 当用户设定新目标时，系统应当基于历史版本的数据提供个性化建议
8. 当生成年度总结时，系统应当突出展示该年度的所有版本发布和重要成就
